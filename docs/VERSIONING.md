# 产品版本策略

FinText-LLM 将产品发布版本与历史实施阶段分开管理。

## 产品版本

产品采用语义化版本 `MAJOR.MINOR.PATCH`，并以 Git tag 作为唯一发布依据：

- `0.x.y`：个人研究工具仍在快速迭代，接口和数据结构可能调整。
- `1.0.0`：核心研究闭环稳定，迁移和兼容策略明确。
- `PATCH`：兼容性修复；`MINOR`：向后兼容的新能力；`MAJOR`：不兼容变更。

仓库目前没有产品发布 tag，因此当前状态是 `Unreleased`。在形成第一个可重复安装、可验证的个人研究闭环后，再发布 `v0.1.0`，不根据历史阶段数量推算版本号。

## 历史实施 ID

旧文档中的 `00`–`21` 只用于追溯实施顺序。目录和文件名暂时保留，以维持链接稳定；新计划不再使用连续的 `V22`、`V23` 命名，而使用能力名称和日期。

历史材料按能力归入四个阶段：

| 阶段 | 历史 ID | 范围 |
| --- | --- | --- |
| Foundation | 00–14 | 数据接入、抽取、搜索、图谱与基础运行时 |
| Risk Studio | 15–17 | 风险工作流、质量层与审计整改 |
| Research Intelligence | 18–19 | 供应链研究、上下文与证据记忆 |
| Agent Runtime | 20–21 | Tool Loop 与全局 Agent 系统 |
