# FinRisk Agent Studio 金融分析师视角项目评估

评估日期：2026-07-11  
评估范围：后端工作流、数据接入、证据体系、图推理、供应链、Agent、质量门、API、测试与面向个人投资研究的能力完整度。

## 1. 结论

FinRisk Agent Studio 已经从年报风险抽取工具发展为证据优先的金融研究工作台原型。它的强项是研究过程可追溯、事实与推断分离、风险路径可解释，以及对 LLM 输出设置质量门。其工程基础明显强于一般个人项目，但当前产品仍然是“风险情报基础设施强、投资决策闭环弱”。

当前成熟度判断：**内部研究工具 / 高质量原型，可用于辅助尽调，不宜独立承担投资决策**。

2026-07-10 执行全量后端测试的结果为 `884 passed, 7 skipped`。跳过项包含真实 SEC、电话会议和浏览器集成，因此该结果证明内部契约稳定，但不能证明所有外部数据链路长期可靠。

## 2. 已完成能力

- FinRisk 主流程覆盖公司解析、SEC 风险抽取、市场证据、证据归一化、风险评分、生命周期判断、图推理、报告和质量评估。
- 供应链模块支持产品依赖发现、递归展开、Sankey、证据绑定和可选 Neo4j 写入。
- Agent runtime 支持 provider-neutral 工具调用、调用预算、trace、证据候选和人工复核。
- 数据层包含 SEC filing、XBRL、transcript、搜索、网页抓取和多 provider 路由。
- 质量层包含 schema、claim grounding、来源质量、financial safety、图路径验证和 fallback 记录。
- API 已具备鉴权、限流、脱敏、可选 SQLite run store 和后台执行路径。
- 前端已覆盖运行发起、过程监控、风险报告、证据图、评估、供应链和 Agent trace。

## 3. 分析师工作流适配度

当前适合：

- 快速阅读 10-K/10-Q 风险披露；
- 为风险收集外部验证证据；
- 识别风险增强、持续或消退；
- 建立公司、产品、供应商、地区、政策的关系；
- 生成可复核的研究初稿；
- 对结论做来源和幻觉检查。

当前无法完整回答：

- 当前价格隐含了怎样的增长和利润率预期；
- 实际结果相对一致预期的差异；
- 风险对收入、毛利率、EPS 和现金流的量化影响；
- Bull/Base/Bear 情景下的估值区间；
- 催化剂何时兑现、观点何时失效；
- 同业之间的风险收益比较与组合仓位约束。

## 5. 关键问题

### P0：已有研究结果未被完整交付

`report_v16` 已包含近期变化、证据表、二阶影响、claim 类型、局限性和下一步问题，但此前前端仅显示风险卡与免责声明；Claim–Evidence Matrix 也固定为空。该问题会直接掩盖项目最具价值的 evidence-first 能力。

### P1：缺财务与估值闭环

风险分数目前更适合称为 Research Priority Score。其 recent signal 主要受网页证据数量影响，novelty 仍为固定基线，且没有把发生概率、财务影响、时间紧迫性和市场未定价程度分开。

### P1：缺历史变化检测

没有可靠的季度快照和差异比较，就无法严肃计算 novelty、管理层措辞变化、风险生命周期和历史判断准确率。

### P1：电话会议没有进入固定季度流程

应重点对比 guidance、需求、库存、ASP、毛利率、capex，以及 prepared remarks 与 Q&A 的差异。

### P2：真实集成验证不足

大量测试依赖 mock/fixture。应建立低频 live smoke，覆盖大盘股、小盘股、异常 filing、缺失 transcript、搜索冲突和 Neo4j 真实读写。

### P2：部分能力尚未接入主研究闭环

机会发现的 schema 与测试实际存在，且全量模块导入检查显示 `180` 个模块均可成功导入；此前基于截断文件清单对该模块作出的“schema 不存在”判断不成立。真实缺口是机会发现 wrapper 仍未使用 ticker 上下文，也没有成为 FinRisk 季度研究主流程的一等产出。应保留全模块 import smoke gate，避免未来出现未被常规测试发现的断链。

## 6. 推荐产品定位

推荐聚焦为：**个人使用、证据可追溯的公司季度研究与投资假设管理系统**。

目标闭环：

```text
建立公司档案 → 拉取最新披露 → 跨期比较 → 更新财务模型
→ 识别预期差和催化剂 → 形成投资假设 → 记录证伪条件
→ 持续监控 → 财报后复盘
```

项目的长期资产不应是更多 Agent，而应是每家公司持续积累的观点、证据、关键变量、证伪条件和结果复盘。

## 7. 建议优先级

1. 完整交付 v16 报告与 Claim–Evidence 数据，建立研究就绪度摘要。
2. 建立季度公司快照和 filing/transcript/XBRL 跨期差异。
3. 加入标准化财务趋势、风险财务映射和 Bull/Base/Bear 情景。
4. 加入用户可维护的市场预期与简单估值。
5. 建立 watchlist、催化剂、证伪条件、提醒和财报后复盘。
6. 最后扩大全市场扫描和更自主的多 Agent 调研。
