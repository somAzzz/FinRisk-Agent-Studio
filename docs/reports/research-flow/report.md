# From annual filing to company investigation

The desk now supports one continuous decision: open an issuer’s filing, inspect the evidence available on a particular date, and follow up on an unresolved question. A new investigation retains a link to its starting question. Its results never replace the historical evidence.

| Analyst task | Friction observed | Implemented behavior |
| --- | --- | --- |
| Find work to review | The queue inferred an Apple risk from the mere presence of a brief and displayed a fixed next-check date. | Today and Research Runs use the same saved records, including filings. The review queue filters for an explicit review status and opens that item. It distinguishes incomplete live results; there is no invented schedule. |
| Work on a filing | Company and annual-report navigation offered competing views of the same snapshot. | One company navigation within the filing: Overview, Financials, Supply chain, Risks & tracking, Evidence & review, Report reader. The issuer, reporting period and cutoff stay visible. Existing links with a return target remain usable. |
| Examine the graph | A candidate relationship or a financial movement can be misread as confirmed attribution. | Reuse the existing relationship, evidence-path and financial views. Show the graph where it answers a supply or exposure question; link to disclosures and distinguish observed changes from attributable impacts. The navigation change does not promote candidates. |
| Investigate a gap | Reading the filing and starting a research run were separate tasks. | Expand a saved tracking question, inspect the direct evidence needed, then open a prefilled draft. Submission is explicit. The API resolves the filing, cutoff and task against the saved snapshot, derives the issuer and document identity, and retains the origin through resume and trace export. |
| Start research | “Runtime settings” opened a launcher; filing analysis exposed raw JSON. | One New research panel asks whether the starting point is a filing or a company question. The filing path takes a local file or public URL, plus an optional goal and cutoff. The company path retains the question, horizon and permitted sources. |
| Set assumptions | Analysts were offered inference, graph traversal and worker settings alongside business inputs. | Analyst requests omit deployment options. Backend defaults select the provider; explicit operator API overrides remain supported. Optional peer valuation assumptions use labeled inputs, including method, period and evidence references. Missing input does not become zero. |

**Walkthrough.** From Today → Review, open Südzucker FY 2025/26. In the 8 November 2026 snapshot the overview links to three tracking questions and two previously reviewed alerts. Open the first question on the EU–Mercosur agreement: exposure and fulfilment are unknown. The investigation draft contains the source-language question, issuer and historical starting date. The existing investigation workflow can gather current evidence; it is not a historical replay engine.

**Verification.** Captured the live filing and entry form before modification, then verified the saved-record → filing → tracking question → investigation draft flow in the browser. Checked the two entry paths and the narrow layout at 390 × 844 (document width 390). The frontend suite passed 84 tests. The backend non-integration suite passed 1,052 tests (8 deselected), including a controlled run/resume against the saved Südzucker task: caller-supplied issuer metadata was replaced, invalid dates/tasks were rejected, and the snapshot remained unchanged. Production and static archive builds passed. No new live model or OCR run was launched for this UX change.

**Boundary.** The workspace displays the evidence lanes actually saved for each filing. Imported reports without a saved tracking snapshot do not acquire a graph or an investigation task simply by appearing in the library. Generic company briefs, peer valuation and journal snapshots are still separate records; they are not joined to an issuer based only on its display name. The remaining integration priority is a stable company identifier across filings, ticker-based briefs and journal entries.
