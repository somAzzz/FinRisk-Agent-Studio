# FinRisk Agent Studio v0.1 规格

状态：Release candidate

包版本：`0.1.0`

## 1. 目标

v0.1 提供一个可以在 demo、cached 和 live 模式运行的个人金融研究工作台。系统必须生成可追溯的证据、结构化研究结果、确定性质量结论和人工复核项。

## 2. 必须支持的产品路径

1. 启动 FinRisk 研究并查看步骤、报告、评分、图和 evaluation。
2. 从 SEC/财务/transcript/risk 结果创建不可变公司快照。
3. 比较两个快照并人工确认、复核或忽略变化。
4. 维护 Thesis、Watchlist、Expectation 和财报后复盘。
5. 建立 Peer Group 并查看财务、风险、预期和估值的分层比较。
6. 执行情景估值、敏感性、市场倍数和简化 DCF。
7. 执行供应链发现、递归扩展并查看证据支持的 Sankey。
8. 查看 Agent tool trace、候选证据并执行人工复核。

## 3. 数据契约

每个研究事实至少包含：

- stable ID；
- ticker/company；
- value 或文本；
- source/source ID；
- observed/published/retrieved 时间；
- `as_of`；
- evidence type；
- lineage 或派生公式；
- component status；
- confidence/review status（适用时）。

Component status：

```text
complete | partial | not_requested | unavailable | failed
```

`not_requested`、`unavailable` 和 `failed` 不能合并成含糊的 `partial`。

## 4. 工作流契约

FinRisk：

```text
resolve → filing → market → normalize → score → lifecycle → graph → report → evaluate
```

Supply Chain：

```text
decompose → search → extract → normalize → expand → graph → evaluate
```

Agent：

```text
plan → select tools → execute → normalize candidates → review gate → finalize
```

每个工作流必须：

- 有稳定 run ID；
- 记录 started/completed/error trace；
- 限制工具轮数、调用数和 token；
- 记录 provider/model/fallback；
- 只把验证通过的证据写入 confirmed state；
- 支持 `completed | needs_review | failed`。

## 5. 质量门禁

v0.1 必须检查：

- Pydantic/schema validity；
- top claim 与 evidence grounding；
- source credibility、freshness 和 diversity；
- financial advice 禁用语言；
- graph path 与 evidence reference 完整性；
- fallback、fixture 和 provider 缺失；
- report disclaimer；
- human review requirements。

硬失败使结果为 `failed`；证据不足、来源单一或需要人工判断时使用 `needs_review`。

## 6. Point-in-time 规则

- 快照创建后不可被新数据静默覆盖。
- `as_of` 之后的 amendment、consensus 修订或 filing 不得进入旧快照。
- expectation 必须保留 observed time，财报后的修订不能用于计算该期 surprise。
- 重复来源和相同 change ID 不得重复生成提醒。
- provider 缺失不能解释为风险消失。

## 7. 图与记忆边界

- confirmed graph edge 必须有 evidence ID。
- LLM 不能创建 confirmed edge。
- hypothesis、candidate 和 confirmed 状态必须分离。
- memory 写入必须记录来源、生命周期和失效条件。
- 不可信或冲突证据进入 candidate/review，不直接进入 active memory。

## 8. 前端

v0.1 包含：

- Today；
- Company Overview/Risks/Financials/Valuation/Management/Supply Chain/Evidence；
- Research Runs；
- Journal。

要求：

- 1440、1024、390px 可用；
- 无页面级横向溢出或 fixed panel 遮挡；
- 键盘焦点可见；
- 支持 reduced motion；
- loading、empty、partial、failed、needs-review 可区分；
- static demo 明确标记 fixture；
- 高级 provider/tool 设置默认次级展示。

## 9. 安全

- 默认 API key 鉴权和 rate limit。
- URL 访问经过 SSRF guard。
- 日志与 trace 不泄露 API key。
- 数据库升级不得通过删表静默丢失研究记录。
- 项目不提供买卖建议、自动交易和仓位管理。

## 10. 验收

发布候选必须通过：

```bash
uv run pytest -q

cd frontend
npm test
npm run build
npm audit --audit-level=moderate
```

并完成：

- 30 个 golden cases；
- 三视口 Chromium smoke；
- 数据库迁移、备份和恢复；
- 至少一条非 demo Research Journal/FinRisk 路径；
- live/provider 跳过项和已知限制记录。

当前结果见 [STATUS.md](../STATUS.md)。

## 11. v0.1 非目标

- 生产级多租户 SaaS；
- 自动投资建议或交易；
- 无人工复核的高风险结论发布；
- 完整实时 segment/consensus/FX 覆盖；
- 任意 provider 永久可用保证；
- 通用聊天机器人作为主产品入口。
